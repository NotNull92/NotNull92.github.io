## 1. 목표와 작업 범위

현재 홈페이지의 북방 마법학교풍 스튜디오 탐험 경험에, 즉각적인 조작 피드백·자연스러운 방 전환·사물별 반응·절제된 환경 움직임을 구현한다. 사용자가 요청한 것은 홈페이지 전반의 애니메이션, 특수효과, Game Feel, Juice 개선이다.

핵심 방향은 **“차가운 북방 성채 안에서, 작은 불빛과 사물이 방문객의 행동에 응답하는 살아 있는 스튜디오”**다. 방문자가 공간에 감탄하고, 사물을 탐색하고, 프로젝트와 팀을 편안하게 알아가는 흐름을 만든다.

이 문서는 조사와 브리핑을 구현으로 연결하는 실행 명세다. 인계 시점에 새로운 효과 코드는 구현되지 않았다. 지금부터 구현·로컬 검증·결과 보고를 진행하면 된다. 문서 전체를 읽은 뒤 이미 정해진 방향을 다시 질문하는 데 시간을 쓰지 말고, 구체적인 구현과 검증으로 이어간다.

### 권한과 경계

- 구현 대상은 이 저장소의 홈페이지와 직접 관련된 검증·문서다.
- 브랜딩, 기존 장면과 캐릭터의 정체성, 프로젝트 내용, 공식 링크, 탐색 구조를 유지한다.
- 커밋·푸시·공개 배포는 이 인계 자체로 요청되지 않았다. 별도 사용자 지시가 없다면 로컬 변경과 검증 결과를 전달한다.
- 기존 사용자 변경을 보존한다. 특히 아래에 기록한 WAV 삭제는 새 효과 작업과 무관한 기존 상태다.
- 막히지 않은 시각 효과 작업은 계속 진행한다. 오디오 원본이 없다는 이유로 전체 구현을 멈추지 않는다.

## 5. 결정된 디자인 방향

### 5.1 감정과 위계

- 입구: 큰 건축과 차가운 바깥, 안에서 새어 나오는 작은 온기.
- 실내: 실제로 누군가 일하고 있다는 조용한 생동감.
- 상호작용: 내가 건드린 대상이 바로 알아듣고 응답하는 느낌.
- 독서·대화: 집중할 수 있는 정적인 중심, 주변 연출은 가라앉음.

시각적 관심의 우선순위는 **현재 입력한 대상 > 읽는 정보 > 배경 환경**이다. 방마다 눈에 띄는 자동 움직임을 여러 개 경쟁시키지 않는다.

### 5.2 유지할 계약

- 학교는 시각적 비유다. 팀은 실제 게임 개발 스튜디오 직원이다. 교사·학생·퀘스트 NPC로 문구를 바꾸지 않는다.
- 로고와 캐릭터의 색·외형, 기존 배경 이미지를 유지한다.
- 프로젝트 책 두 권, 인물 여섯 명, 방 다섯 개, 기존 공식 링크를 유지한다.
- 프로젝트 기록은 서고의 책을 선택해서 연다. 대화 선택지에 새로운 프로젝트/방 이동 지름길을 넣지 않는다.
- `college`라는 내부 파일명·클래스명, room hash, 저장 키를 미관상의 이유로 바꾸지 않는다.
- 영어 기본, 저장된 한국어 선택, 읽기 위치 복원, 키보드 접근을 유지한다.
- 색·타이포그래피·기본 레이아웃의 전체 표는 `DESIGN.md`를 따른다.

### 5.3 이번 구현에서 제외

- 화면 전체 흔들림, 강한 플래시, 글리치, 색수차, 전면 색종이 효과.
- 커서 추적 입자·커스텀 커서·버튼이 포인터를 따라 도망가는 동작.
- 스크롤 강제 제어, 큰 카메라 줌, 포인터를 따라 움직이는 전체 배경.
- 모든 인물이 계속 떠다니거나 튀는 idle loop.
- 강제 타이핑 대사, 입장/독서를 막는 연출 대기 시간.
- 점수·퀘스트·보상 상자·가짜 로딩·가짜 빌드 성공 상태.
- React 전환, GSAP/Motion/Three.js 등 새 모션 라이브러리, 자체 범용 효과 엔진.

실제 눈깜빡임·옷자락 움직임은 현재 단일 이미지에 프레임이 없으므로 별도의 아트 제작 과제다. 이번에는 CSS 왜곡으로 얼굴을 깜빡이게 만들거나 인물을 늘였다 줄이지 않는다.

| 환경 밝기 변화 | 약 4–8초 | 진폭 작게, 서로 다른 위상 |
| 서고 먼지 | 약 10–18초 | 소량·저대비·제한된 공간 |

기존 `--fast`, `--select`, `--turn`, `--arrival`, `--ease`를 먼저 검토하고 같은 의미에 새 토큰을 중복 생성하지 않는다. JS에 같은 값이 별도로 하드코딩된 지점과 CSS 값의 불일치를 확인한다. 필요한 한두 값을 공유하는 정도로 해결하고 설정 시스템을 만들지 않는다.

재질별 느낌을 다르게 한다. 돌·금속은 짧고 명확하게 정지, 종이·책갈피는 약한 후속 움직임, 불씨는 위로 이동하며 소멸한다. 기존 `cubic-bezier(.22,1,.36,1)`를 기본으로 재사용한다.

### 6.2 전역 모션 제어

현재 모션 버튼은 입구에만 보이고 `.scene-weather`를 제어한다. 방 진입 WAAPI는 OS 설정만 보고, 책은 자체 `matchMedia`를 본다. 새 효과를 넣기 전에 이 차이를 정리한다.

구현할 동작:

1. 모든 방에서 모션 제어에 접근할 수 있다. 헤더의 기존 제어 묶음에 배치하는 것을 기본안으로 검토한다. 모바일 헤더의 공간과 한/영 길이를 실제 확인한다.
2. 사이트의 사용자 선택은 기존 `ember-motion-paused`를 재사용한다. 방 전환이 선택을 초기화하지 않는다.
3. 최초 방문은 OS `prefers-reduced-motion`을 따른다. 현재 디자인의 명시적 Play 허용 정책은 유지하되, 이 정책이 어느 효과에 적용되는지 코드에서 일관되게 처리한다.
4. 이번 기본안은 명시적 Play가 장식 모션을 재허용하는 것이다. OS가 새로 reduce 상태로 바뀌면 재생 허용을 해제하고 즉시 정지한다. OS가 다시 no-preference가 되어도 사용자의 수동 정지 선택을 덮어쓰지 않는다.
5. 수동 정지/움직임 감소 시 환경 loop는 멈추고 새 장식 이동 효과는 시작하지 않는다. 기존 페이지 넘김과 임시 전환도 정리한다. 현재 내용·선택 테두리·알림·탐색 기능은 그대로 사용할 수 있다.
6. 탭이 숨겨지면 환경 loop를 멈추고, 일회성 효과/전환은 완료 상태로 정리하거나 취소한다. 돌아올 때 지난 효과를 몰아서 재생하지 않는다. 저장된 사용자 선택 자체는 바꾸지 않는다.
7. 책/대화창이 열린 동안 방의 환경 효과는 일시 정지한다. 모달 자신의 조작 피드백·책장 넘김은 전역 허용 상태에 따라 동작할 수 있다.
8. 모달을 닫으면 현재 방과 사용자 설정에 맞는 환경만 재개한다. 모달로 인한 일시 정지는 저장하지 않는다.
9. 모션 정지는 오디오 음소거와 별개다. 소리는 기존 명시적 사운드 선택을 따른다.

읽기 기준 하나와 환경 정지 조건 하나 정도로 구성한다. 예: 전역 장식 모션 허용 여부를 확인하는 작은 함수, 여기에 modal-open 조건을 추가한 환경 모션 여부. `BookReader`에는 기존 옵션 객체로 작은 predicate/callback을 전달하는 정도를 우선 검토한다. 이벤트 버스·상태 머신 라이브러리·새 클래스를 만들 필요가 없다.

초기화 순서에 주의한다. 현재 `BookReader`는 모듈 상단에서 생성되며 모션 상태 변수는 하단에서 초기화된다. 콜백을 추가하더라도 생성 시 아직 초기화되지 않은 변수를 읽지 않게 한다.

CSS `animation-play-state`만으로 JavaScript의 `element.animate()`까지 제어된다고 가정하지 않는다. WAAPI 취소/종료와 `reader.stopTurn()`을 필요한 상태 변경 경로에서 명시적으로 처리한다. 전역 정지 상태가 `#scene`에만 있으면 형제 요소인 두 dialog에는 적용되지 않으므로 root/body 범위를 검토한다.

native dialog가 열리면 배경 헤더는 inert다. 모달 안에서도 모션 제어를 제공하거나, Escape로 닫은 뒤 설정하는 경로와 OS 설정 즉시 반영을 명확히 보장한다. 배경 버튼이 모달 위에서 클릭될 것으로 기대하지 않는다.

### 6.3 공통 입력 피드백

- 기존 `.control`, `.primary-action`, `.scene-link`, `.volume`, `.actor`, `.tool`, `.rune-control`, `.outbound-portal`의 상태를 확인한 뒤 보강한다.
- 버튼의 작은 눌림은 `:active`, 키보드의 위치 안내는 `:focus-visible` 등 기본 기능을 우선한다.
- 키보드와 터치는 기능이 동일해야 한다. 모바일에서 호버를 먼저 열기 위해 두 번 탭하게 만들지 않는다.
- `.actor`, `.room-path`, `.rune-control`, `.library-books`는 위치에 이미 transform을 사용한다. 공통 `transform: translateY(...)` 규칙으로 `translateX(-50%)`를 덮어써 위치가 틀어지지 않게 한다.
- 부드러운 그림자 이동이 필요한 경우 큰 blur 값을 계속 애니메이션하기보다 작은 장식 레이어의 opacity를 사용한다.
- 의미 있는 클릭 반응은 클릭한 대상 근처에 둔다. 하단 toast만 바뀌는 것으로 끝내지 않는다.
- 장식은 `pointer-events:none`, 필요한 경우 `aria-hidden=true`. 포커스 가능한 장식이나 중복 읽기 항목을 만들지 않는다.

## 7. 구현 명세: 장면과 개별 상호작용

### 7.1 방 전환 — 최우선

현재 `renderRoom()`은 배경의 `src`를 바꾸고 전경에 520ms 투명도/위치 애니메이션을 적용한다. 새 작업에서는 배경까지 약 240–320ms로 연결되게 한다.

- 최소 구현 후보는 임시 배경 레이어 하나를 사용한 짧은 크로스페이드다. 동일한 장면 전체를 재구성하는 새 라우터는 필요 없다.
- 논리적인 방 선택, hash, 내비 현재 상태, 제목, 저장 상태와 실제 표시 장면이 최종적으로 일치해야 한다.
- 뒤로 가기·앞으로 가기·직접 hash 진입·저장된 방 복원도 기존 공통 경로를 유지한다.
- 사용자의 다음 탐색을 애니메이션 완료까지 막지 않는다. 빠른 연속 이동에서는 마지막 의도가 이긴다.
- 배경 decode나 preload를 추가하면 요청 번호 또는 동등한 최소 장치로 오래된 완료를 버린다. 이미지 준비를 기다리는 동안 클릭 반응은 즉시 주고, 실패해도 콘텐츠와 탐색은 사용할 수 있어야 한다.
- 이미지 교체 실패로 이전 방 그림과 새 방 핫스폿이 무기한 함께 남지 않게 한다. 방의 기본 배경/설명과 정상 탐색으로 안전하게 마무리한다.
- 장면을 스냅샷/복제한다면 복제본은 입력 불가·접근성 트리 제외·중복 id 제거·완료/취소 후 제거가 필요하다. 현재/임시 배경 수는 제한되어야 한다.
- 새 방 진입 시 기존 rune timer, 도구 효과, 전환 레이어, 이전 방 notice 및 그 타이머를 정리한다. 새 방과 무관한 상태 문구가 남지 않아야 한다.
- 전환으로 포커스를 잃거나 헤더/본문 위치가 점프하지 않게 한다. 현재 방 제목으로 옮기는 기존 의미를 유지한다.
- 처음 페이지가 열릴 때 인트로 대기 화면을 추가하지 않는다.

### 7.2 입구 — 이미 있는 분위기를 연결

- 현재 눈 28개, 오로라, 문 주변 glow를 출발점으로 삼는다. 별도의 전면 파티클 시스템을 겹치지 않는다.
- 입장 버튼 또는 문 핫스폿의 hover/focus에 문 주변의 따뜻한 빛이 약간 강해진다. 키보드에도 대응한다.
- 모바일은 기존 별도 입구 이미지 `entrance-mobile.webp`를 사용하므로 광원 위치를 데스크톱 좌표 그대로 복사하지 않는다.
- 로고 이미지와 건축물을 회전·왜곡하지 않는다. 입장 연출이 실제 이동을 지연하지 않는다.
- 추가 불씨가 꼭 필요하다면 문 근처의 한 번 반응으로 제한하고, 기존 눈 밀도를 늘리지는 않는다.

### 7.3 홀 — 촛불과 대표 룬 반응

환경:

- 실제 촛불/화로가 있는 소수의 위치에 작은 따뜻한 glow를 배치한다.
- 4–8초 정도의 느린 저진폭 opacity 변화. 화면 전체 밝기 또는 건물 전체의 색조를 흔들지 않는다.
- 글자·명패·얼굴 주변을 지속적으로 밝게 번쩍이게 하지 않는다.

룬의 제안 타임라인:

| 입력 이후 | 보여 줄 반응 |
| --- | --- |
| 0ms | 입력 접수: 작은 눌림/윤곽 강조가 즉시 시작 |
| 약 0–300ms | 기존 세 조각이 40–60ms 정도 차이로 정렬. 최초 움직임 앞에 대기 시간을 넣지 않음 |
| 약 250–380ms | 마지막 조각이 맞물리는 순간 룬 영역 안에 얇은 파동 하나 |
| 약 300–650ms | 3–6개의 작은 호박색 픽셀이 위로 흩어지고 잔광 소멸 |
| 이후 | 다음 입력이 가능한 안정 상태. 기존 상태 알림은 별도로 읽을 시간 제공 |

- 이전 `.active` 클래스·세 조각 구조·`sound.effect('rune')`를 재사용한다.
- 기존 800ms 룬 회전 CSS와 새 타임라인이 이중으로 적용되지 않게 한다.
- 재클릭은 이전 일회성 반응을 정리하고 새 반응으로 갱신한다. 여러 setTimeout이 과거 시점에 새 상태를 해제하지 않게 한다.
- 일반 클릭 전체를 막는 debounce로 해결하지 않는다.
- OS/수동 모션 정지에서는 완성 상태·색·읽을 수 있는 알림으로 결과를 전달한다.
- 사운드가 꺼져도 완결된 피드백이어야 한다. 효과음 동기화를 위해 입력이나 전체 UI를 정지시키지 않는다.

### 7.4 서고 — 먼지, 종이와 책갈피

- 빛이 드는 제한된 구역에 6–10개 정도의 작은 저대비 먼지부터 시도한다. 모바일은 더 적게 사용한다. 초기 수치이며 화면을 보고 줄일 수 있다.
- 먼지는 책 본문 위에 나오지 않는다. 책을 열면 환경 움직임을 멈춘다.
- `.volume-cover`의 들림·회전과 `.book-ribbon`의 기존 이동을 유지하면서 시간 관계를 다듬는다.
- 책갈피에 한 번의 작은 후속 움직임, 페이지 넘김에 작은 그림자 opacity 변화를 검토한다. 책·dialog·leaf가 각각 크게 움직이는 중복 연출을 추가하지 않는다.
- `BookReader.goTo()`가 먼저 인덱스와 내용을 갱신하고 장식 leaf를 나중에 붙이는 순서를 유지한다. `animationend`를 기다려야 페이지 내용이 바뀌는 구조로 바꾸지 않는다.
- 다음/이전 연속 입력, 첫/끝 경계, 섹션 이동, 한/영 변경, 700/701px 전환, Escape에서 leaf가 남지 않아야 한다.
- 책을 열었던 버튼으로의 포커스 복원, 책별 정확한 페이지 저장을 유지한다.
- 복잡한 표지→전체 화면 3D 변형이나 새 책 렌더러는 이번에 만들지 않는다.

### 7.5 도구 — 작업 성격이 보이는 세 반응

현재 세 도구는 모두 동일한 `.tool-marks` 세 개와 같은 tool 효과음을 사용한다. 작은 DOM/CSS/SVG 장식으로 시각적 개성을 구분한다.

| 대상 / 데이터 ID | 제안 반응 | 제한 |
| --- | --- | --- |
| Mora / `build` | 짧은 선 세 개가 어긋난 위치에서 일정한 패턴으로 정돈됨 | 실제 빌드·테스트가 실행됐다는 성공 메시지를 만들지 않음 |
| Star / `test` | 메모 옆 작은 체크 표시가 나타나고 안정됨 | 가짜 통과 개수·점수·진행률 없음 |
| Pixie / `pixels` | 3–5개의 색상 픽셀이 작은 색상 견본으로 모였다가 사라짐 | 캐릭터/작품 전체 재색칠 없음, 브랜드와 인물 팔레트 존중 |

- 새 반응은 버튼 바로 근처의 충분한 공간에 배치한다. 캐릭터 얼굴과 제목을 가리지 않는다.
- 기존 `traces`와 번역을 우선 유지한다. 실제 정보 변경이 필요 없으면 문구를 늘리지 않는다.
- 장식 개수는 고정 상한을 둔다. 같은 도구의 재클릭은 현재 반응을 대체한다.
- 현재 코드도 클릭마다 이전 `.tool-marks`를 제거하므로 이를 무제한 누수라고 오진하지 않는다. 새로운 장식/타이머에도 동일하게 제한과 정리를 적용한다.
- 모바일은 첫 탭으로 즉시 실행되며 최소 터치 영역을 유지한다.

### 7.6 캐릭터와 대화

- 기존 hover/focus 명패·말풍선 반응을 일관되게 다듬는다. 인물 몸 전체를 늘리거나 지속적으로 띄우지 않는다.
- 캐릭터 선택 직후 해당 대상의 선택 반응을 보여 준다. 초상화 decode 동안 무응답으로 보이지 않게 한다.
- `openConversation()`의 이미지 decode와 `conversationRequest` 보호를 유지한다. 이미지 실패 시 텍스트 대화는 열릴 수 있어야 한다.
- 요청 A 뒤 요청 B를 선택했거나 방을 바꿨을 때 A 초상화가 나중에 대화창을 덮어쓰면 안 된다.
- 대화창은 작은 이동/투명도로 빠르게 나타난다. 기존 native dialog, Escape, 초점 트랩·복원을 유지한다.
- 질문을 누르면 답변 전체를 바로 갱신하고 작은 연결 효과만 적용한다. 글자별 출력·음절 소리 반복·텍스트 깜빡임을 넣지 않는다.
- `aria-live`에 장식 프레임마다 텍스트를 넣지 않는다. 실제 답변 변경만 알린다.
- 대화가 열린 동안 방의 환경 loop는 멈춘다. 대화를 닫는 시점에는 저장된 모션 선택을 존중한다.

### 7.7 외부 채널의 문

- hover/focus된 문에만 문양 주변·가장자리의 작은 따뜻한 빛을 강조한다.
- 출구 네 개를 동시에 강하게 맥동시키지 않는다.
- 링크는 기존 `<a href>`의 기본 동작을 유지한다. 애니메이션 때문에 외부 이동을 `setTimeout`으로 미루거나 새 창 동작을 바꾸지 않는다.
- 모바일 레이아웃은 문 네 개의 2열 배치와 배경 구도가 다르다. 고정 문 좌표가 정확히 맞지 않으면 실제 선택 UI 근처의 강조를 우선한다.

## 8. 환경 레이어·성능·오디오 구현 조건

### 8.1 환경 레이어

- 현재 장면은 `isolation:isolate`, 배경/날씨/그늘에 음수 z-index를 사용한다. 추가 레이어가 배경 뒤에 가려지거나 전경 위에서 입력을 막지 않게 확인한다.
- 배경은 기본적으로 한 장의 WebP다. 촛불, 창문, 문을 실제 별도 오브젝트처럼 이동시킬 수 있다고 가정하지 않는다. 이번 효과는 그림 위의 작은 빛·먼지·상태 장식이다.
- `object-fit:cover` 때문에 원본 그림의 좌표와 뷰포트 백분율은 항상 일치하지 않는다. 화면 폭에 따라 광원이 벽/얼굴 위로 이동하면 위치를 보정하거나 그 효과를 줄인다.
- 별도 범용 좌표 보정 엔진을 만들기 전에 최소한의 breakpoint 배치로 해결 가능한지 확인한다.
- 실내 환경 효과는 현재 방에만 생성하거나 표시한다. 보이지 않는 방을 계속 애니메이션하지 않는다.

### 8.2 성능

- 우선 `transform`·`opacity`를 사용한다. `top/left/width/height`를 매 프레임 갱신하는 효과는 피한다.
- 큰 blur, filter, 그림자 변화는 비용을 측정한 뒤 필요할 때만 사용한다. 픽셀 아트가 뿌옇게 보이지 않게 한다.
- 새 canvas/WebGL, 상시 requestAnimationFrame 루프, pointermove 상태 추적은 이번 범위에 필요하지 않다.
- `will-change`를 모든 요소에 영구 적용하지 않는다. 측정된 문제가 있을 때 좁은 범위에 사용한다.
- 애니메이션 완료·취소·모션 정지·방 전환·모달 닫힘에서 임시 노드/타이머/WAAPI를 정리한다. 동일 상태에서 레이어 수가 계속 증가하면 실패다.
- 60Hz 화면에서 부드러운 재생을 목표로 하되 측정 없이 “60fps 보장”이라고 보고하지 않는다. 테스트 기기/뷰포트/도구와 관찰 결과를 적는다.
- 로딩 시간·터치 반응·본문 가독성이 나빠지면 장식 밀도부터 줄인다.

### 8.3 오디오

- 기존 `CollegeSound`의 opt-in, 제스처 활성화, room crossfade, 독서 감쇠, 숨김 탭 suspend를 재사용한다.
- 현재 효과음은 한 voice만 유지해 반복 입력에 제한이 있다. 효과음을 겹겹이 쌓는 별도 사운드 엔진을 만들지 않는다.
- 같은 시각 반응에 소리를 맞추되, 예약된 소리가 다른 방이나 음소거 뒤에 재생되지 않게 한다.
- hover마다 소리를 재생하지 않는다. 사운드 활성화 후 의도적인 조작에만 짧게 반응한다.
- BGM 파일 누락은 3.3절의 기존 조건이다. 원본 없이 음악 품질·방별 음악 재생 검증을 완료했다고 말하지 않는다.
- 파일 복원 여부는 사용자가 정할 사안이다. 복원 지시가 오기 전에는 다른 시각 작업을 완료하고 사운드 제한을 보고한다.

종료 조건: 사물별 반응이 명확하고 오래된 타이머나 레이어가 새 상태를 침범하지 않는다.

2. 홀의 국소 조명, 서고의 먼지, 공방/문 공간의 절제된 조명을 배치한다.

종료 조건: 배경에 생동감이 있지만 텍스트와 조작 대상이 더 명확하게 보인다.

## 10. 최소 변경 원칙과 테스트 설계

- 기존 공통 함수를 먼저 고친다. 버튼마다 서로 다른 이벤트 로직을 복제하지 않는다.
- `college.js`, `college.css`, 필요 시 `index.html`·`book.js`를 중심으로 수정한다. 새 문구/음색을 실제로 추가할 때만 locale/sound를 수정한다.
- 새 모듈은 중복된 실제 책임을 줄일 때만 만든다. 명세를 보고 선제적으로 motion engine/registry/config 폴더를 만들지 않는다.
- CSS 파일이 압축되어 있고 뒤쪽에 override가 있다. 전체 재포맷으로 diff를 크게 만들지 말고 관련 규칙과 최종 cascade를 확인한다.
- 사용자 지정값도 아닌 모든 시간·좌표를 외부 설정 파일로 빼지 않는다. 조정이 필요한 소수 토큰만 둔다.
- 새로 생기는 분기/취소/상태 동기화는 실행 가능한 작은 검사 하나 이상으로 보호한다. Node 기본 `assert` 또는 의존성 없는 브라우저 harness 등 현재 환경에 맞는 최소 방식으로 작성한다.
- 좋은 회귀 대상은 “빠른 A→B 이동 뒤 늦은 A 완료가 B를 덮어쓰지 않음”, “정지 후 페이지 넘김이 장식 leaf를 만들지 않으면서 인덱스는 바뀜”, “반복 룬 입력에서 오래된 종료가 최신 반응을 해제하지 않음”이다.
- 단순히 소스에 특정 클래스 문자열이 있다는 검사만으로 모션 동작 검증을 대체하지 않는다. 새 프레임워크·대규모 mock DOM을 만드는 것보다 실제 브라우저에서 검증 가능한 작은 재현을 우선한다.
- 기존 `book-check.mjs`는 페이지 논리를 확인하지만 실제 CSS 모션/레이어/포커스를 검증하지 않는다. 브라우저 QA도 필요하다.
- `sound-check.mjs`를 녹색으로 만들기 위해 파일 검증을 삭제하거나 누락을 성공으로 처리하지 않는다.

## 11. 실행 명령과 QA 체크리스트

### 11.1 실행 환경

작성 환경은 Windows PowerShell, Node.js `v24.12.0`이다. 프로젝트 경로는 `C:\Users\PC\Desktop\Cowork\NotNull92.github.io`였다. 다른 환경에서는 전달받은 저장소 루트에서 실행한다.

```powershell
git status --short
git rev-parse HEAD
python -m http.server 4173 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:4173/#entrance`를 연다. 서버는 종료 전까지 해당 셸을 사용하므로 검사는 다른 터미널에서 실행한다. 이미 서버가 있으면 본인 작업용인지 확인해서 재사용하고 다른 프로세스를 임의로 종료하지 않는다. 이전 에이전트의 실행 세션이나 브라우저 핸들이 남아 있다고 가정하지 않는다.

`file://`로 직접 열지 않는다. ES modules를 사용하므로 HTTP가 필요하다.

```powershell
node scripts/check.mjs
node scripts/book-check.mjs
node scripts/sound-check.mjs
node --check assets/college.js
node --check assets/book.js
node --check assets/sound.js
git diff --check
```

새 검사를 만들면 명령을 최종 보고에 포함한다. 이 문서에 새 검사 파일 이름이 예시로 언급되더라도 이미 존재한다고 가정하지 않는다.

최소 시각 증거는 다섯 방의 desktop/mobile 화면, 책, 대화, 룬/도구 반응을 포함한다. 정적 캡처만으로 타이밍 품질을 입증할 수 없으므로 가능하면 짧은 녹화 또는 실제 동작 관찰 기록을 남긴다. 환경·폭·언어·모션 상태를 증거에 붙인다.

## 12. 완료 기준과 최종 보고 형식

아래를 만족해야 이번 구현을 완료로 보고할 수 있다.

- 공통 조작 피드백, 배경 방 전환, 룬, 세 도구의 반응이 구현되어 있다.
- 입구의 기존 효과를 보존하고 실내의 국소 조명/서고 먼지가 테마에 맞게 동작한다.
- 책·대화의 연출이 콘텐츠 접근과 재사용을 늦추지 않는다.
- 전역 정지·OS 설정·숨김 탭·모달 집중 상태가 CSS와 JS 효과에 일관되게 적용된다.
- 모바일·키보드·언어·읽기 위치·기존 링크에 새 회귀가 없다.
- 반복 입력과 빠른 방 이동에서 오래된 효과가 남지 않는다.
- 새 의존성이나 불필요한 엔진이 도입되지 않았다.
- 기존 검사의 실제 결과와 필요한 새 회귀 검사/브라우저 QA 결과를 기록했다.
- `DESIGN.md`와 `docs/VALIDATION.md`에 최종 결정과 이번 날짜의 증거·한계를 덧붙였다. 과거 검증을 덮어써 새 결과처럼 만들지 않았다.

오디오 원본 부재가 끝까지 남으면 “시각 효과 구현 완료, 실내 음악 통합 검증은 기존 WAV 누락으로 미완료”처럼 구분한다. 전체 검사 PASS나 모든 요구 완료로 뭉뚱그리지 않는다.

Grok의 최종 답변은 다음 정보를 포함한다.

1. 사용자에게 보이는 변경과 파일 목록.
2. 최종 조정한 주요 시간·효과 강도 및 구현에서 달라진 부분.
3. 실행한 검사 명령과 실제 결과.
4. 브라우저 확인 범위와 캡처/녹화/관찰 기록 위치.
5. 기존 WAV 누락 등 남은 조건과 검증하지 못한 부분.
6. 로컬 확인 URL, 커밋/배포 여부. 하지 않은 일을 했다고 보고하지 않는다.

## 15. Suggested skills / 사용할 수 있을 때의 작업 지침

이 문서는 특정 스킬이나 Codex 도구가 없어도 실행할 수 있게 작성했다. Grok 환경에 설치되어 있지 않은 스킬 이름을 호출할 수 있다고 가정하거나, 스킬 설치를 구현의 선행 조건으로 만들지 않는다.

- `frontend-design`: 해당 스킬이 있으면 현재 판타지·픽셀 테마에 일관된 움직임을 고르고 화면을 검토할 때 사용한다. 기존 브랜딩을 새 취향으로 교체하는 근거로 쓰지 않는다.
- `ponytail` 또는 `ponytail:ponytail`: 해당 스킬이 있으면 full 수준으로 적용한다. 기존 코드→기본 CSS/브라우저 기능→최소 코드 순으로 선택한다. 접근성·실패 처리·검증은 생략하지 않는다.
- 브라우저/컴퓨터 사용 스킬: 해당 환경에서 실제 제공하는 것으로 로컬 QA를 수행한다. 이 문서에 나온 이전 에이전트의 도구명이나 핸들을 그대로 호출하지 않는다.
- `handoff`: 세션을 다시 넘겨야 할 때만 완료/미완료/실패와 증거 위치를 갱신한다.

## 16. 사용자용 전달 방법과 시작 프롬프트

### 저장소를 직접 편집할 수 있는 Grok

저장소의 현재 작업 폴더와 이 문서를 제공한다. 먼저 아래 프롬프트를 붙이고, 문서 전체와 현재 소스를 읽도록 한다. GitHub URL만 전달하는 경우 이 새 문서는 아직 커밋되지 않았으므로 별도로 첨부해야 한다.

### 웹 채팅 형태의 Grok

이 문서와 현재 프로젝트 파일을 함께 첨부한다. 가능하면 `.git`, 임시 실행물, 이전 증거 묶음을 제외한 현재 프로젝트 사본을 ZIP으로 전달한다. 문서만 전달하면 실제 코드·그림의 구조를 충분히 확인할 수 없다.

전송 크기를 줄여야 한다면 우선 다음 자료를 포함한다.

- 루트: `index.html`, `works.html`, `college.html`, `README.md`, `DESIGN.md`.
- 소스: `assets/college.js`, `college.css`, `book.js`, `sound.js`, `language.js`, `locale.js`, `project-records.js`, `legacy-route.js`.
- 시각 자산: `assets/scenes/`, `assets/characters/`, `assets/fonts/`, `assets/logo.png`, `assets/favicon.png`. 기본 경로 검사까지 동일하게 실행하려면 다른 참조 자산도 포함한다.
- 검증: `scripts/`.
- 문서: 이 인계문, `docs/CONCEPT-HISTORY.md`, `docs/VALIDATION.md`, `docs/ASSETS.md`.
- 오디오: 현재 존재하는 경우만 원본 `assets/audio/`를 포함하고, 없다면 3.3절의 누락 상태를 함께 전달한다.

다섯 방의 현재 화면을 함께 주면 시각적 판단에 도움이 된다. 다만 스크린샷만으로 구현하도록 하지 않는다. 코드 실행이 불가능한 Grok이라면 파일별 패치를 받아 로컬에서 적용·검증해야 하며, 그 단계 전에는 구현 완료나 브라우저 검증 완료가 아니다.

아래를 새 Grok 대화의 첫 메시지로 사용할 수 있다.

```text
Ember Studio 홈페이지에 모션·Game Feel·Juice 개선을 실제 구현해줘.

첨부한 docs/GROK-MOTION-IMPLEMENTATION-HANDOFF.md 전체와 현재 저장소를 먼저 읽어줘. 이 문서는 조사·브리핑을 구현으로 이어가기 위한 상세 명세이고, 새 효과 코드는 아직 구현되지 않았어.

방향은 “차가운 북방 성채 안에서, 작은 불빛과 사물이 방문객의 행동에 응답하는 살아 있는 게임 스튜디오”야. 현재 디자인·브랜딩·콘텐츠를 유지하고, 공통 조작 피드백과 방 전환부터 룬·도구별 반응, 실내 환경, 책·대화 마감까지 문서의 순서대로 완성해줘.

이미 결정된 방향을 다시 브리핑하는 데 그치지 말고 코드를 수정하고 검증해줘. 기본 CSS와 브라우저 기능, 기존 코드를 재사용하고 새로운 모션 라이브러리나 범용 엔진은 추가하지 마. 키보드·모바일·한국어/영어·움직임 감소·전역 정지·빠른 연속 입력까지 보존해줘.

기준 커밋은 e791393f00f0737c8a2a23e918ca347931ee2e3a지만 실제 전달된 작업 트리를 우선 확인해. 로컬에서는 BGM WAV 4개가 이미 삭제되어 sound-check가 실패했어. 기존 사용자 변경을 임의로 되돌리거나 검사를 약화시키지 말고, 시각 작업을 진행하면서 오디오 검증 제한을 따로 보고해줘.

최종적으로 변경 파일, 실제 실행한 검사와 결과, 브라우저 확인 증거, 남은 제한을 알려줘. 커밋·푸시·공개 배포는 하지 마.

파일 편집·실행·브라우저 접근이 실제로 없다면 없는 기능으로 작업했다고 말하지 말고, 필요한 자료를 확인한 뒤 적용 가능한 파일별 패치를 제공해줘. 수행하지 못한 검증은 미실행으로 표시해줘.
```
